# Freedom Arrow 0.1 on Linux

**Use the prepared .bamod with BAModManager running under Proton. This candidate keeps vanilla detection, stealth and concealment. Custom scoring currently works only inside guarded Local AI Skirmish; this is not a verified multiplayer release.**

## 1. Get and check the package

The review branch is `codex/0.1-deployment`. From a terminal:

```bash
git clone --branch codex/0.1-deployment --single-branch https://github.com/Cole-Graham/freedom-arrow.git
cd freedom-arrow
python3 releases/0.1/verify.py
(cd releases/0.1 && sha256sum -c SHA256SUMS.txt)
```

The package is `releases/0.1/FreedomArrow-0.1.1.bamod`. You can also download that
file with GitHub's **Download raw file** button. It is a ZIP-format modpack;
import it in the manager rather than copying it into `Mods` as a single file.

This build pins game build **26273833** and the corresponding generated IL2CPP
assemblies. A newer native game build or a changed generated wrapper is refused with a build
mismatch. Version 0.1.1 ignores only the random module ID when checking generated
wrappers; all other bytes remain pinned. Do not turn off the hash checks to get past that error: send the log
so compatibility can be reconciled.

## 2. Prepare BAModManager

Download the author's compiled **BAModManager v1.1.0**:

<https://github.com/Speer-BA/BAModManager/releases/download/1.1.0/BAModManager-v1.1.0.zip>

Extract the **whole ZIP**, keeping the DLLs beside `BAModManager.exe`. Run that
EXE through Proton as shown below. BAModManager manages arbitrary packages;
BAModLauncher is the separate program configured for a particular modpack.
You do not need to compile anything to use this release.

Optional source build: the vendored manager can be cross-published from Linux
with the **.NET 8 SDK**. This writes a Windows program to run through Proton:

```bash
dotnet publish thirdparty-tools/BAModManager-main/BAModManager.csproj \
  -c Release -r win-x64 --self-contained true \
  -p:EnableWindowsTargeting=true -p:AppFlavor=Manager \
  -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true \
  -p:DebugType=none -o "$HOME/Applications/BA-ModManager"
```

That exact cross-publish command was built during preparation. The full manager
GUI/import workflow has not been re-tested in this task. The earlier game test
used the same launcher's direct modded launch route through Proton.

## 3. Run the manager through Proton

Keep Steam open. In Steam, use **Broken Arrow → Properties → Installed Files →
Browse** to find the game. Use the Proton version that already runs the game on
your machine; the earlier isolated test used Proton 11.0. Set the paths below
to your actual library. The paths shown are examples, not automatic discovery.
Steam Flatpak and secondary libraries use different locations.

```bash
fa_steam="$HOME/.local/share/Steam"
fa_proton="$fa_steam/steamapps/common/Proton 11.0/proton"
fa_compat="$fa_steam/steamapps/compatdata/1604270"
fa_manager="$HOME/Applications/BA-ModManager"
fa_package="$PWD/releases/0.1/FreedomArrow-0.1.1.bamod"

env STEAM_COMPAT_CLIENT_INSTALL_PATH="$fa_steam" \
    STEAM_COMPAT_DATA_PATH="$fa_compat" \
    SteamAppId=1604270 SteamGameId=1604270 \
    WINEDLLOVERRIDES="version=n,b" \
    "$fa_proton" run "$fa_manager/BAModManager.exe" "$fa_package"
```

`fa_compat` is the Broken Arrow prefix in the game's Steam library. The override
lets the native MelonLoader `version.dll` load. Do not run the Windows manager
with Linux `dotnet`; use Proton as shown.

The native-DLL override is documented by [MelonLoader's official Wine/Proton
guide](https://github.com/LavaGang/MelonWiki/blob/master/docs/gettingstarted.md).
[Valve's Proton documentation](https://github.com/ValveSoftware/Proton) explains
Steam's launch-option environment variables.

## If Broken Arrow is greyed out in MelonLoader Installer

**The generic MelonLoader Installer 4.4.0 disables games whose folder contains
`EasyAntiCheat`.** This is a deliberate installer check, separate from finding
the game or its Proton prefix. The reported screenshot shows this installer,
not BAModManager. Adding the same game manually uses the same protection check.

Close that installer and use **BAModManager → MelonLoader → Install MelonLoader**
through Proton as described above. BAModManager downloads/extracts the loader
archive directly. Keep the game's anti-cheat files intact and use the explicit
**Play Anti-Cheat Disabled** Steam entry for guarded local tests.

Verified against the installer's exact
[4.4.0 protection check](https://github.com/LavaGang/MelonLoader.Installer/blob/4.4.0/MelonLoader.Installer/GameManager.cs)
and [disabled-button binding](https://github.com/LavaGang/MelonLoader.Installer/blob/4.4.0/MelonLoader.Installer/Views/GameControl.axaml).
This explains the original installer screenshot. A later SSH repair confirmed
the installed payload and fixed the missing Steam DLL override. First startup
then installed .NET Runtime 6.0.36 automatically and generated the wrappers.

## 4. Install and launch

1. In BAModManager, browse to the folder containing `BrokenArrow.exe`. Under the
   Wine file picker, the Linux filesystem is normally available through `Z:`.
2. Install MelonLoader using the manager's **MelonLoader** page if needed. Let
   the first initialization finish. The mod requires generated game assemblies.
3. Import the supplied `.bamod` if the command-line import has not already
   offered it. Enable **Freedom Arrow 0.1.0**. Disable old QA/ActualArrow/other
   Freedom Arrow packages first; shared DLL paths and scoring hooks can conflict.
4. In Broken Arrow's Steam Properties, set the selected launch option to
   **Play Anti-Cheat Disabled**. In the text **Launch Options** field, set:

   ```text
   WINEDLLOVERRIDES="version=n,b" %command%
   ```

   Start the game from Steam using that selected entry. The manager is used for
   installation and mod management here. Its Windows Steam-process check can
   fail to recognize Linux Steam, so its PLAY button is not required for this
   Linux procedure. Do not select the ordinary anti-cheat launch entry while
   this package and MelonLoader are enabled.
5. In the game menu, press **F8** for the package's **Local AI Skirmish** setup.
   Pick a valid map/deck and start that guarded local battle. Native Skirmish's
   label alone does not establish offline play; do not bypass a warning that
   native Skirmish is closed with mods.

The scoring compatibility correction completed a guarded 30-minute Local AI
Skirmish with AI spawning, normal captures and native Victory. Selected armor
values are checked in the armory; full combat/loadout acceptance remains open. The native scoreboard/timer are used; the black
information box, progress bar and developer editor are absent.

## 5. Check that it loaded

Use the manager's MelonLoader log button or open `MelonLoader/Latest.log` under
the game folder. Look for:

```text
FREEDOM_ARROW_PAYLOAD_VERIFIED: 34 files
FREEDOM_ARROW_APPLIED: 7 tables, 8624 fields
```

`UserData/FreedomArrow/runtime-receipt.json` records applied fields.
`runtime-failure.txt` means loading was refused or failed; send that file and
the log. A successful receipt proves database loading, not every ability or
combat interaction. The custom mode must also report its guarded local setup
and pass a real capture/tick/contest/end test on this revised package.

Stealth, sensors and concealment should remain vanilla. Ground balance changes
include the selected HP/armor, AT ammunition, APS, smoke, sprint and infantry
ammo edits. See [the evidence and remaining gaps](../../releases/0.1/EVIDENCE.md).
Cover damage reductions, passenger overdamage and final destruction scoring are
absent, and no final point goal is imposed. The scenario sets match duration.

## 6. Roll back

Close the game. In BAModManager, disable/uninstall this package. Use the existing
**Play vanilla with no mods** control to remove/park the loader proxy, or uninstall
MelonLoader through the manager if its Windows launch check prevents that action.
Remove the temporary DLL override and restore your normal Steam launch selection. Keep the same prefix so the
manager can find its installed-package record and backups.

This modpack does not replace `GameAssembly.dll` or `data.unity3d`. Do not copy
modified game bundles or a QA GameAssembly over your Steam installation. If the
game does not exit, identify its exact game process before stopping it; do not
kill every Wine/Proton process or other running games.

## What was verified here

The mod DLLs and manager were cross-built on Linux. Archive/hash checks, the
actual loader's payload verification, all expected table comparisons, 41
runtime checks and 74 scoring/HUD host checks passed. No game or desktop was
launched for this deployment preparation. The earlier live native-scoreboard
test used the prior QA archive; the revised AI-enabled archive and this full
Linux install flow still need live acceptance.

## Startup repair in 0.1.1

If the game appears vanilla and `MelonLoader/Latest.log` is absent, first check
the Steam DLL override above. First initialization can take several minutes.
The observed 0.7.3 bootstrap automatically installed the missing Windows .NET
Runtime 6.0.36 inside the game prefix, then generated the game assemblies.

The original 0.1.0 conquest check compared a random wrapper module ID and could
refuse otherwise identical generated assemblies. Version 0.1.1 masks only that
16-byte ID for generated wrappers; native game, other wrapper bytes, settings
and payload integrity checks remain active. Never remove the compatibility
checks. The same update makes base T-90M side HEAT 200 mm while its Additional
ERA (2017) and ERA + Arena upgrades stay at 400 mm.
